# راجح | رؤية الأسواق — بوت تسجيل المهتمين ولوحة العملاء

النسخة الثانية من الكود باسم راجح | رؤية الأسواق، جاهزة للإعداد والتشغيل. لم تُربط ببوت حقيقي أو تُنشر على Railway؛ يلزم إنشاء البوت وإضافة المتغيرات أدناه.

## تجربة العميل

1. يضغط العميل Start فيستقبل صورة ورسالة ترحيب، ثم يختار: الأسهم السعودية، الأمريكية، أو الاثنين.
2. يكتب اسمه.
3. يكتب رقم واتساب برمز الدولة، أو يشارك رقم هاتفه من تليجرام.
4. يراجع بياناته ويؤكد موافقته على التواصل معه لتفعيل التجربة.
5. يتلقى الشكر وأن خدمة العملاء ستعود إليه لتفعيل التجربة المجانية.

رقم واتساب قد يختلف عن رقم تليجرام. فحص الرقم يتحقق من الصيغة الدولية فقط؛ لا يتحقق من ملكيته أو وجود حساب واتساب. الاسم والرقم والسوق لا تُعتمد حتى يؤكد العميل. إعادة Start لا تنشئ حسابًا مكررًا. تعديل البيانات ثم الإلغاء يحافظ على البيانات السابقة. الحسابات المختلفة التي تستخدم نفس رقم الهاتف تُعرض كتنبيه داخل ملف العميل، ولا تدمج تلقائيًا.

## لوحة الإدارة

- تسجيل الدخول بكلمة مرور، ومفتاح جلسات سري.
- إجمالي من بدأوا التسجيل، المكتملين، الطلبات الجديدة، والتجارب المفعلة.
- إحصاء الاهتمام بالسعودية والأمريكية والاثنين، ومصادر الإعلانات.
- بحث بالاسم والرقم وUsername وTelegram ID.
- فلترة بالسوق، الحالة، اكتمال التسجيل، المصدر، تاريخ الدخول، والمتابعات المستحقة.
- ترتيب على مستوى جميع النتائج ثم تقسيم الصفحات، 30 عميلًا لكل صفحة.
- ملف العميل: روابط تليجرام وواتساب والاتصال، حالة المتابعة، المسؤول، موعد المتابعة، وسجل ملاحظات.
- الحالات: جديد / تم التواصل / التجربة مفعلة / مشترك / غير مهتم.
- إرسال رسالة فردية عبر البوت، مع حالة انتظار الإرسال أو التسليم أو الفشل.
- تصدير النتائج المطابقة للفلاتر إلى CSV بصيغة UTF-8 يمكن فتحها في Excel.
- رقم تليجرام والهاتف يصدران كنص لتجنب فقدان الأرقام أو تفسيرها كصيغة في Excel.

النسخة الحالية تستخدم حساب إدارة مشتركًا، وحقل المسؤول هو اسم للمتابعة؛ لا توجد حسابات موظفين منفصلة أو صلاحيات متعددة. لا توجد رسائل جماعية أو إرسال تلقائي على واتساب. التفعيل في اللوحة يسجل الحالة فقط؛ الربط بخدمة توصيات فعلية ليس جزءًا من هذه النسخة. التواريخ والفلاتر في هذه النسخة بتوقيت UTC كما هو موضح في الواجهة.

## التشغيل على GitHub وRailway

### 1. إنشاء البوت

من @BotFather على تليجرام: /newbot، ثم اختاري الاسم وUsername ينتهي بـ bot. احفظي التوكن في متغير BOT_TOKEN فقط. لا تضعي التوكن أو قاعدة العملاء في GitHub. هذه النسخة لا تحتاج API_ID أو API_HASH أو ملف session.

لإعداد الاسم والوصف والصور اتبعي ملف BOTFATHER_AR.md المرفق. رسالة الترحيب بعد /start داخل core.py والصورة المرسلة من assets/rajih_welcome.png.

### 2. رفع الكود

فكي الضغط وارفعِي محتويات مجلد stock_leads مباشرة إلى مستودع GitHub خاص جديد، بحيث يظهر Dockerfile في جذر المستودع. لا ترفعي الملفات المولدة محليًا مثل leads.db أو .env.

### 3. إنشاء قاعدة البيانات

في مشروع Railway جديد، أضيفي خدمة PostgreSQL. البوت ولوحة الإدارة يستخدمان نفس DATABASE_URL من هذه الخدمة. لا تستخدمي SQLite لخدمتين منفصلتين على Railway؛ ملفاتهما المحلية لا تُشارك، وقد تضيع عند إعادة النشر.

### 4. إنشاء خدمة لوحة الإدارة أولًا

أضيفي خدمة من مستودع GitHub وسمّيها stock-admin. يستخدم Dockerfile أمر التشغيل الافتراضي:

python -m gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 60 wsgi:app

أضيفي المتغيرات:

| المتغير | القيمة |
| --- | --- |
| DATABASE_URL | Reference إلى DATABASE_URL لخدمة PostgreSQL نفسها |
| BRAND_NAME | راجح | رؤية الأسواق |
| SECRET_KEY | قيمة عشوائية تنتج من setup_admin.py |
| ADMIN_PASSWORD_HASH | الهاش الناتج من setup_admin.py |
| COOKIE_SECURE | 1 |

لتوليد القيم على Windows داخل مجلد الكود:

```powershell
py -m pip install -r requirements.txt
py setup_admin.py
```

البرنامج يطلب كلمة مرور قوية وتأكيدها، ثم يطبع الهاش ومفتاح الجلسات لإضافتهما إلى Railway. لا تضعي كلمة المرور نفسها في المتغير ADMIN_PASSWORD_HASH. إذا كان جهازك يستخدم python بدل py، استبدلي py بـ python.

انتظري نجاح الخدمة، ثم أنشئي لها Public Domain وافتحي الرابط HTTPS؛ ستكون صفحة تسجيل الدخول. يمكن استخدام /health كمسار Healthcheck لهذه الخدمة. عامل ويب واحد مقصود لتوحيد عداد محاولات الدخول في هذه النسخة.

### 5. إنشاء خدمة البوت

أضيفي خدمة ثانية من نفس المستودع باسم stock-bot، وحددي Custom Start Command:

python bot.py

متغيراتها:

| المتغير | القيمة |
| --- | --- |
| BOT_TOKEN | توكن البوت الجديد من BotFather |
| DATABASE_URL | نفس مرجع قاعدة PostgreSQL المستخدمة في stock-admin |
| BRAND_NAME | راجح | رؤية الأسواق |
| ADMIN_TELEGRAM_IDS | اختياري: رقم حسابك على تليجرام، أو أرقام مفصولة بفواصل |

خدمة البوت لا تحتاج Public Domain أو Healthcheck HTTP. شغلي نسخة واحدة فقط، وعطّلي Serverless/النوم إن كان مفعّلًا كي يستمر استقبال التحديثات. أثناء تغيير النشر، أوقفي النسخة القديمة قبل تشغيل الجديدة لتجنب عمل اثنتين معًا.

لمعرفة رقم حسابك، بعد تشغيل البوت افتحيه وأرسلي /id. ضعي الرقم الناتج في ADMIN_TELEGRAM_IDS ثم أعيدي نشر العامل. إرسال /id لا يضيف حسابًا لقائمة العملاء. أي حساب إداري يرغب باستقبال إشعارات يجب أن يفتح البوت ويرسل /id أولًا.

إذا كان للبوت Webhook سابق، يرفض العامل بدء Polling حتى يزال؛ الأسهل استخدام بوت جديد مخصص لهذا المشروع.

### 6. اختبار حقيقي بعد الربط

- سجلي كعميلة تجريبية واختاري الاثنين.
- أدخلي اسمًا ورقمًا دوليًا، ثم أكدي التسجيل.
- تأكدي من ظهور العميل مرة واحدة في لوحة الإدارة.
- أضيفي ملاحظة وغيّري الحالة إلى تم التواصل.
- أرسلي رسالة فردية إلى حساب التجربة وتحققي من استلامها.
- جرّبي التصدير وإعادة تشغيل العامل بعد إدخال الاسم؛ يجب أن تبقى خطوة إدخال الهاتف محفوظة.

## تتبع مصادر الإعلانات

استخدمي مثلًا:

https://t.me/YOUR_BOT_USERNAME?start=ksa_ad_01
https://t.me/YOUR_BOT_USERNAME?start=us_ad_01

استبدلي YOUR_BOT_USERNAME باسم البوت. المصدر يقبل حروفًا إنجليزية وأرقامًا وشرطة وشرطة سفلية؛ لا يتجاوز 64 حرفًا. يُحفظ أول مصدر صالح قبل اكتمال التسجيل؛ إعادة الدخول لا تغيّره. هذا يقيس دخول البوت والتسجيلات، ولا يسحب تقارير Telegram Ads أو تكلفة الإعلان تلقائيًا.

## الحفظ واستكمال العمل

حالة التسجيل والبيانات والتحديثات المعالجة ومؤشر Polling وطابور الرسائل تُحفظ في قاعدة البيانات. انقطاع الشبكة لا يمسح التقدم. الطلبات التي أرسلتها Telegram ولم تُعالج بعد تعتمد كذلك على مدة احتفاظ Telegram بالتحديثات؛ استمرار التوقف لفترة طويلة قد يفقد بعض التحديثات القديمة.

عند حظر العميل للبوت، يظهر فشل التسليم وحالة blocked. رسائل الشبكة أو rate limit تُعاد مع انتظار. يوجد احتمال نادر لتكرار رسالة إذا استلمتها Telegram ثم تعطل العامل قبل تسجيل نجاح الإرسال، لأن sendMessage لا يوفر مفتاح منع تكرار. تسجيل العميل نفسه محمي من تكرار التحديثات.

## تشغيل محلي للتجربة

إعداد المتغيرات في PowerShell قبل فتح كل عملية:

```powershell
$env:DATABASE_URL="sqlite:///leads.db"
$env:BRAND_NAME="راجح | رؤية الأسواق"
$env:COOKIE_SECURE="0"
$env:SECRET_KEY="القيمة الناتجة من setup_admin.py"
$env:ADMIN_PASSWORD_HASH="الهاش الناتج من setup_admin.py"
$env:BOT_TOKEN="التوكن"
```

لتشغيل لوحة الإدارة محليًا:

```powershell
py -m flask --app wsgi:app run --host 127.0.0.1 --port 8080
```

وفي نافذة ثانية داخل نفس المجلد، مع نفس DATABASE_URL وتوكن البوت:

```powershell
py bot.py
```

افتحي http://127.0.0.1:8080. وضع COOKIE_SECURE=0 للتجربة المحلية فقط؛ يبقى 1 على HTTPS في Railway. ملف .env.example مثال للمتغيرات، ولا يتم تحميل .env تلقائيًا؛ استخدمي متغيرات البيئة.

## الاختبارات المنفذة

```powershell
py -m unittest discover -s tests -v
```

تغطي الاختبارات التسجيل الكامل، حفظ مرحلة التسجيل، منع إعادة معالجة التحديث، الهاتف العربي والصيغة الدولية، رفض مشاركة جهة اتصال لشخص آخر، إلغاء التعديل، حماية الإدارة وCSRF، الفلاتر، تعديل المتابعة، منع المراسلة قبل الموافقة، التصدير الآمن، ومحاكاة إعادة الإرسال عند Telegram 429 والحظر 403.

نجحت الاختبارات العشرة محليًا باستخدام SQLite ومحاكاة Telegram، بما فيها صورة الترحيب وأزرارها وإرسال الصورة multipart والعودة للنص عند غياب ملف الصورة. لم يُجر اختبار بوت حقيقي أو قاعدة PostgreSQL مستضافة بعد؛ يتم ذلك بعد إضافة الإعدادات.
